# Plan 5.1: Queue Models, Additive Migration, Database Constraints & Safe Pre-Checks

## Objective
Enhance the `QueueEntry` model and PostgreSQL schema with daily queue scoping (`queue_date`), user-friendly token strings (`token_display`), triage/cancellation notes (`notes`), and database-enforced concurrency protection against multiple simultaneous consultations per doctor (`uq_active_doctor_in_consultation`), backed by an additive, reversible Alembic migration with strict data consistency pre-checks.

## Context
- `backend/app/models/queue.py`
- `backend/alembic/versions/`
- PostgreSQL 18.6 `medismart_db`

## Safety & Architecture Rules
1. **Database-Level Integrity Constraints**:
   - `queue_date: Mapped[date] = mapped_column(Date, server_default=func.current_date(), index=True, nullable=False)`
   - `token_display: Mapped[str] = mapped_column(String(20), nullable=False)` (e.g., `Q-001`)
   - `notes: Mapped[Optional[str]] = mapped_column(Text, nullable=True)`
   - **PostgreSQL Partial Unique Index**:
     `CREATE UNIQUE INDEX uq_active_doctor_in_consultation ON queue_entries (doctor_id, queue_date) WHERE status = 'in_consultation';`
     Guarantees at database engine level that no two patients can be marked "in consultation" with the same doctor at the same time.
   - **Daily Token Numbering Index**:
     `CREATE UNIQUE INDEX uq_doctor_date_token_number ON queue_entries (doctor_id, queue_date, token_number);`
     Prevents token numbering collisions for a given doctor on any clinic day.
2. **Safe Migration Pre-Checks**:
   - Verify existing status values in `queue_entries` are allowed (`waiting`, `in_consultation`, `completed`, `skipped`, `cancelled`).
   - Halt safely if any anomalous rows exist without dropping or modifying data.
3. **Additive-Only Execution**:
   - Zero table drops, recreations, or truncations.
